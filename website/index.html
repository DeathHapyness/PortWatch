01 · O que é

Observação sem intrusão

PortWatch é um projeto pessoal de monitoramento para homelabs com Docker. Ele responde, em um só lugar: o que está rodando, em quais portas, em quais redes — sem instalar nada nos containers e sem arriscar o daemon.

A coleta acontece pelo Docker Engine API, sempre intermediada pelo docker-socket-proxy: um componente que expõe apenas os endpoints de leitura do daemon. O módulo de coleta (netprobe) transforma essas respostas em um resumo consolidado, servido pela API FastAPI em /api/v1/system/summary.

O consumo é livre: dashboard web, terminal com curl ou qualquer cliente HTTP. Cada decisão estrutural está registrada nos ADRs (Architecture Decision Records) do repositório.

Somente leitura

Nenhuma rota de escrita. O backend não conversa direto com o socket do Docker.

Sem agente invasivo

Nada é instalado dentro dos containers observados. A fonte é a Engine API.

Decisões documentadas

Cada escolha relevante vira um ADR versionado no repositório.

Pensado para homelab

Leve, auto-hospedado e simples de rodar com um make dev.

Objetivo

  • Descobrir containers, imagens e estados em execução
  • Mapear portas publicadas e portas livres no host
  • Listar redes Docker e seus participantes
  • Consolidar tudo em uma resposta única da API
  • Visualizar rapidamente em um dashboard web

03 · Funcionalidades

O que ele faz hoje

Cada capacidade abaixo já tem implementação ou ADR correspondente no repositório.

Descoberta de containers

O netprobe lista containers em execução com imagem, estado e tempo de vida direto da Engine API.

Mapa de portas

Cruza portas publicadas pelos containers com as portas ocupadas no host para revelar também as livres.

Redes Docker

Inventaria redes e quem participa delas — base para entender isolamento e comunicação entre serviços.

API REST consolidada

FastAPI com resposta única em /api/v1/system/summary — pronta para dashboards, scripts e automações.

Dashboard web

Interface React + Vite para consulta rápida do estado do host, alimentada pela API de observação.

04 · Arquitetura

Fluxo somente-leitura, de ponta a ponta

Do daemon Docker até a sua tela, nenhum componente consegue alterar o ambiente observado.

hostHomelabDocker Engine + containers em execução, redes e portas publicadas.
read-onlydocker-socket-proxyFachada que expõe apenas os endpoints de leitura da Engine API. Escritas são bloqueadas aqui.
fastapiPortWatch backendO netprobe coleta containers, portas e redes; a API serve o resumo consolidado.
uiDashboard webReact + Vite consultando a API de observação.
clicurl / scriptsQualquer cliente HTTP consome o mesmo resumo.

Decisões detalhadas nos ADRs 0001–0005: escolha do proxy, formato do resumo, política somente-observação e o ambiente de desenvolvimento isolado (portwatch.env=dev-sandbox).

05 · Segurança

Vigiar sem tocar

Monitorar não deveria criar risco. O PortWatch foi desenhado para ser o componente menos privilegiado do host.

Acesso intermediado

O docker-socket-proxy filtra a Engine API: só leitura chega ao daemon. O socket Unix nunca é montado diretamente.

Somente-observação

Nenhuma rota inicia, para ou modifica containers. A política somente-observa vale para coleta e para a API.

Configuração por ambiente

Segredos e ajustes vivem em variáveis de ambiente — nunca no código. Desenvolvimento usa o perfil isolado portwatch.env=dev-sandbox.

Menor privilégio

Container dedicado, capacidades mínimas e superfície reduzida: a API só responde GET.
